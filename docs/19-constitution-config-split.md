# 19 · 宪法与配置分离（参数出宪 + 两级配置中心）

> 状态：spec 草案 r10（2026-09-10）。**D1 与通用默认已合一裁决（r9）：全局单一口径 50-项目库/60-知识库/70-工作区**；D2–D4、E1–E3 按推荐执行。**20 号 spec §2 红线修订表述已获用户确认=宪法修订授权**。r7/r8：主会话两轮自查修复（9 P1+6 P2）；r9：通用默认合一；**r10：独立盲审修复（red-teamer@volces2——其"须重大修订"总判定经核验下调为"修 P1 后可执行"：spec-implementation gap 系误判（C2/C3 即待办票）；真修复=快照时机与恢复语义（§3.4）、配置表格解析约定与 normalize 细则（§3.1/§3.2）、升级手册在册清单空校验（§6-1.2）、tag 异地备份说明（§6-0.3）、项目 schema 增 auto_push_remote（20 号联动）**。
> 一句话：宪法 AGENTS.md 只承载全项目恒同的不变式（零参数、逐字节恒等可比）；一切项目/机器可变的参数迁入两级级联配置中心（机器级 + 项目级 `harness.config.md`），治理机制对两者用不同语义——宪法=恒等比对，配置=schema 校验。

## 1. 背景与问题

### 1.1 现状机制

AGENTS-template.md 采用「」span 整体替换制（docs/17 §3 S5），安装问答把 **7 类参数固化进宪法正文**：

| # | 参数 | 模板位置 | 归属层 |
|---|---|---|---|
| 1 | 项目名（标题） | 标题 span | 项目级 |
| 2 | 一句话定位 / 技术栈 / 构建命令 / 测试命令 / 目录速览 | 项目快照 5 条 span | 项目级 |
| 3 | agent 名 ×3 + 项目名角标 ×1 | 知识库行 | 机器级 |
| 4 | 知识库三区号（10/20/30，S5 第七问可调） | 知识库行 | 机器级 |
| 5 | 规范仓 docs 绝对路径 | 文档地图 span | 机器级 |

### 1.2 矛盾（三处活例）

1. **sync 只能日期近似**（sync-harness.mjs:120-128，ca3b1ab 引入）：各项目宪法正文嵌不同参数 → 内容级比对不可行 → 退化为 constitution-affecting-baseline 日期 vs 项目定稿日。模板 bump 后人工对照**无法机器区分"合法定制"与"漂移"**。
2. **本机 2 条恒久 DRIFT**（planner/archiver 钉旧分区版）：角色文件内置同款默认区号（17 S5① 自述"需一并调整"）→ 一次定制需 AGENTS.md + 两角色文件三处同步，同步不了就永久挂账。
3. **时效数据住进宪法**：模板维护点自述"测试命令等时效性字段随里程碑更新"——改一个测试命令被迫走宪法人工修订流程。

### 1.3 根因

不变式（规则）与变量（数据）合并在同一文件，导致：定制通道（安装问答渲染）与治理通道（sync 基线比对）冲突；宪法无法跨项目模板化同步；参数变更被错误赋予宪法级修订成本。

## 2. 目标与非目标

**目标**
- G1 宪法零参数：AGENTS-template.md 渲染机制整体退役，新装=原样复制，全项目逐字节恒等。
- G2 两级配置中心：机器级一份（全机共享）+ 项目级一份（每项目），级联解析，git 版本化。
- G3 治理分语义：sync 对宪法做恒等比对（零歧义 DRIFT），对配置做 schema + 可达性校验。
- G4 红线等强扩容：harness.config.md 与 AGENTS.md 同级"只能人改"，杜绝宪法后门（agent 改配置绕过治理）。
- G5 根治挂账：本机 2 条角色文件恒久 DRIFT 随角色参数化消失。

**非目标**
- 不做配置服务/热加载（单机单仓场景，文件 + git 足够）。
- 不改变六角色流水线、hooks 架构、记忆四层——本票只动"参数的住所"。
- 不做多机集中配置管理（机队巡检仍走 sync --check 只读报告）。

## 3. 架构设计

### 3.1 两级级联配置

```
解析优先级：项目级 > 宿主级 > 共享级 > 内置默认（默认值只活在配置模板示例行与安装器问答里，不进宪法）

机器级  ~/.agents/Harness-Configuration/       （独立目录，寿命不绑规范仓 clone——r4 用户裁决）
          ├ common.config.md    共享参数（vault 根、三区名、规范仓路径）
          └ <host>.config.md    宿主参数（zcode/claude/kimi/codex/opencode/pi…每宿主一份）
项目级  <项目根>/harness.config.md             （宿主无关：不进 .zcode/——宪法层 Codex/OpenCode 原生可读，配置层同规）
```

每份配置文件末尾内建修订记录表（日期/变更/动机），人工跟踪变更（§3.4）。级联：common < host < project，低层可被高层覆盖。

common.config.md schema v1：

| 键 | 默认（示例） | 说明 |
|---|---|---|
| schema | 1 | 配置版本，供未来迁移 |
| vault_root | ~/Documents/MyObsidian | Obsidian 库根（S1 问答落此） |
| zone_final_project | 50-项目库 | 项目定稿区（只能人写） |
| zone_final_common | 60-知识库 | 通用定稿区（只能人写） |

注：上表示例值=**通用默认（r9 裁决：与 D1 本机值合一，全局单一口径）**；agent 段=`10-<agent 名>`、项目段缺省=`50-项目库/10-ZCODE/<项目名>`。原 10/20/30 编号自 v3 起退役（同步改：模板示例、check-env 默认、S5 问答默认、docs/01/03 表述——C7/C12 覆盖）。

项目级 schema v1：

| 键 | 默认（示例） | 说明 |
|---|---|---|
| schema | 1 | 配置版本 |
| project_name | （目录名） | 项目名；basic-memory `--project` 按其小写派生 |
| one_liner | 待补 | 一句话定位（planner 首个 spec 校正） |
| tech_stack | 待补 | 技术栈 |
| build_cmd / test_cmd | 待补 | 构建/测试命令（developer 首票确认） |
| dir_brief | （安装器生成） | 目录速览一行图 |
| checkpoint_every | 3 | 可选：自治链检查点间隔票数（20 号 spec A7） |
| auto_push_remote | （无） | 可选：允许自动 push 的 remote 名/URL（20 号 §4；**无人配置=不自动 push**） |
| project_segment | （派生式） | 知识库项目段；缺省= `<zone_final_project>/<agent_segment>/<project_name>`，可覆盖 |

格式：Markdown 表格（键|值|说明）。理由：人 + LLM 双读、说明列即内建注释、与文档地图哲学同构；校验器（node）按行解析只验存在性与值格式（路径合法、区号 `^\d+-`），不需要完整解析器。**解析约定（r10 盲审补）**：以表头行 `| 键 | 值 | 说明 |` 识别表格起点、仅解析表格内行；说明列禁用半角 `|`（用全角｜替代）；表外行（前言/修订记录）不参与键值解析；schema 键缺失=配置非法（fail-loud，不静默猜版本）。

### 3.2 治理语义对照

| 对象 | 治理机制 | 判定 |
|---|---|---|
| AGENTS.md（零参数宪法） | sync 恒等比对（**normalize 细则（r10）：统一 LF + strip UTF-8 BOM，即以无 BOM 的 LF 形态为比对基准**——防 CRLF/BOM 双向假 DRIFT）后逐字节 vs 模板 | 任何差异 = 宪法漂移 [DRIFT]，零歧义 |
| harness.config.md ×2 | sync/check-env schema 校验 + 关键路径可达（vault_root 存在、三区目录在位） | 缺失/非法 = [WARN]/[FAIL] + fail-loud 条款兜底 |
| 角色文件（templates/agents/） | 恒等分发（既有机制不变） | 参数出正文后模板源与部署副本恢复可恒等 |

### 3.4 治理与防线

- **项目级配置**：项目根路径不匹配 guard 白名单（guard-worktree.mjs:55 allow=['/docs/','/memory/','/context.md','/templates/']）→ **默认即拦**，与 AGENTS.md 同机制，零代码变更即受保护。
- **机器级配置（r4 治理模型，用户裁决：独立目录 + common/host 分层 + 人工线下管理）**：
  - **住所与分层**：`~/.agents/Harness-Configuration/` 独立目录（安装时无则新建），与规范仓 clone 生命周期解耦——clone 重装/换位不波及配置。目录内分两层：`common.config.md`（全机共享参数，单份）与 `<host>.config.md`（宿主异构参数，每宿主一份，安装时无则新建）。分层与既有口径同构：宿主异构件按宿主分套（hooks 先例）、全机共享件单份（规范仓/skills 先例）——**共享参数若随宿主整拆成 N 份，改 vault/三区需同步 N 处、漏一处即跨宿主分裂**（用户原案风险，分层即修正）。
  - **变更留痕（弱审计）**：每份配置文件**末尾**内建修订记录表，**固定三列 `| 日期 | 变更 | 动机 |`、只追加不改写（r10 定格式）**；人工修订时顺手追加一行；`sync --check` 维护各文件内容 hash 快照（`~/.zcode/harness-config-state.json`，与 harness-projects.json 同域——寿命独立于配置目录，兼作误删恢复副本），**快照时机（r10 明确）：首建=安装 S7 验收通过后/升级阶段 3.2 工具 v2 首跑时，此后每次 --check 结束更新；恢复=人工执行（工具打印 cp 命令建议、不自动写回——与人工线下管理一致）**；hash 变而修订记录末行（表格末行）未变 → [WARN] 提醒补记——机器可判定的最低审计。
  - **耐久性**：独立目录根治"clone 重装丢失"；残余风险=目录/文件误删，对冲：`sync --check` 检测"在册项目非空而 common 或在册宿主文件缺失"→ [FAIL]，按状态快照恢复。
  - **变更权与红线两阶段（r5 用户裁决）**：配置红线分两阶段——**安装阶段不入红线**（agent 可写配置以完成安装：首装生成 common+host、加装补建宿主文件、按问答落值），**安装结束即入红线**（此后机器配置只能人工线下修订——agent 任何场景只备料给建议 diff，人执行；项目级配置由 guard 拦截、机器级配置由条文约束）。影响面多大就在哪层改——单项目差异用项目级覆盖（该值住该项目 git），单宿主差异改该宿主文件，确属全机变更才改 common。"在某项目工作期间想改三区"的多数正确动作是该项目覆盖，而非动全局。
  - **放弃 git 级审计属知情决策**：单机个人信任模型下变更频率极低；若未来扩多人/多机集中管理，须升级为专属仓制（r2 方案于本仓 git 历史留档）。

## 5. 安装流程 v3（S5 重写要点）

1. **机器级配置两分支**（S1/S5）：
   - **无机器级配置（首装机器）**：新建 `~/.agents/Harness-Configuration/` + `common.config.md` + 本宿主 `<host>.config.md`（S1/S5 机器级问答：vault 根、三区名、本宿主 agent 段；安装窗口豁免同宪法——agent 生成 + 人复核 = 人授权；各文件修订记录表首行 `init <host/日期>`）；默认值取配置模板示例行；生成后 check-env 验证三区可达（目录尚未建立属允许状态，报告提示）。
   - **已有机器级配置（已装机器加装项目）**：**只读沿用，机器级问题不再问**；本宿主文件缺失则仅新建该宿主文件（common 不动）。向人展示当前生效值一行摘要（vault/三区/agent 段）供过目；人如坚持改全局：提示存量项目即时受影响，走 §3.4 人工线下修订，并建议移出安装会话单独进行。配置存在但解析失败 → 安装中止先修（fail-loud）；schema 版本旧 → 按版本字段提示迁移。
2. **S5① 项目级七问**照常 → 项目级 harness.config.md；project_segment 缺省按派生式从机器配置计算；AGENTS.md → **原样 cp 模板，零渲染**，人复核即授权（安装窗口豁免语义保留但简化）。
3. **降级路径**（已武装机器加装项目）：**仅项目级文件**的渲染稿落 docs/（白名单可写），给人一条 move 命令，move 后删渲染稿；**机器级文件不走此路径**（r7 收窄）——已武装机器的装机前提=机器配置已在，缺失即"在册非空而配置缺失"异常态 → 安装中止报错（fail-loud），不做项目内渲染中转（防机器资产短暂滞留项目工作树、被 ② 的 git add docs 误收入库——9239bb6 同型风险）。
4. **S7 验收单**新增：sync 恒等比对 [OK]（AGENTS.md vs 模板）+ 配置 schema 校验 [OK]。
5. **红线切换点（r5）**：S7 验收通过=安装窗口关闭，两级配置自此刻入"只能人改"红线——项目级 guard 于新会话生效（项目根路径本就不在白名单）、机器级条文即时生效；与 AGENTS.md 落位后红线恢复同拍。

## 6. 在装项目升级手册（r6，影响最小=四阶段分步收敛）

设计原则：**每个新读者出现前，它要读的东西必须已在**——零参数宪法是配置的第一个读者（阶段 2 落位前须先有机器/项目配置），参数化角色是最后一个读者（阶段 3 重铸前所有项目配置须就位）。反向排布会让未升级项目停摆（fail-loud）或静默错位。四阶段每阶段末全机一致可运行；机队仅 web2api/AITrader2，一次升级窗口完成（D4）。

### 阶段 0：前置与规范仓升级（一次性）

| 步 | 操作 | 验证 |
|---|---|---|
| 0.1 | 机队盘点：`sync --check` 记录现状基线（含 2 条钉版 DRIFT） | 输出存档 |
| 0.2 | 各项目在飞工单清零：`git gtr list`/report-worktrees 无未合并 feat 分支（有则先收或明确搁置）；**清零后至阶段 3.4 验收通过=流水线冻结期，不开新票**（r7：新宪法读新分区+旧角色写旧分区的混合态下，任何走到归档的工单都会把笔记写进已废弃的旧分区） | 全空或有据 |
| 0.3 | 规范仓打回退锚点 tag：`git tag pre-v3-config-split`——**本地 tag 即可，勿 push 公开仓**（r7：污染公开标签）；**异地备份（r10 补）：将 tag 名与指向 commit 记入私有备忘（本地 tag 不随 push 传播，开发机损坏即丢锚点）** | tag 可见 |
| 0.4 | 规范仓升级：pull v3（含 T1–T5 产物：零参数模板/两配置模板/角色参数化源/sync v2/check-env v2/pre-merge 脚本/adapters 重铸）。**源区分（r8）**：本机（dev 机）直接用开发仓 Zcode_T1 工作树；其他消费机（标准位 clone）**须待 T7 发布完成后再执行本手册** | `git log -1` |

**预期噪音**：0.4 后 `sync --check` 转红（模板源新 vs 部署副本/项目宪法旧）——升级窗口内属预期，阶段 3 末全绿；期间**勿跑 `--apply`**（角色源已是读配置版，部署到无配置项目会停摆）。

## 8. 验收标准

- AC1 **恒等**：迁移后 sync --check 对 web2api、AITrader2 报宪法恒等 [OK]；人为改动任一项目 AGENTS.md 一行 → [DRIFT]。
- AC2 **配置驱动**：改项目级 test_cmd 后新会话 agent 采用新值；改机器级 zone_workspace → planner/archiver 无需改动即按新值定位（角色提示词零分区字面量，grep 验证）。
- AC3 **红线**：agent 尝试改项目根 harness.config.md → guard exit=2（模拟 payload 实弹）。
- AC4 **安装回归**：全新项目走 S5 v3 → 生成两配置 + AGENTS.md 与模板逐字节恒等；已武装机器降级路径两文件均通。
- AC5 **挂账清零**：本机 planner/archiver 2 条恒久 DRIFT 消失（sync 全绿）。
- AC6 **fail-loud**：临时移走机器配置 → check-env [WARN] 且角色行为=停下报告不臆造（条款评审或演练）。
- AC7 **机器配置耐久与留痕**：a) 在册项目非空而 common 或在册宿主文件缺失 → sync --check [FAIL]（实弹）；b) 人工修订未补修订记录 → 下次 sync [WARN]（hash 快照比对）；c) 模拟误删配置目录 → [FAIL]，按 `~/.zcode/harness-config-state.json` 快照可恢复。

## 9. 风险与对冲

| 风险 | 对冲 |
|---|---|
| 间接层：用参数前多读一文件 | 渐进披露本就是体系哲学（文档地图"按需读取"）；宪法变短变稳定，净成本≈0 |
| 配置悬空/被删 → 宪法条款引用落空 | fail-loud 条款（§3.3）+ check-env 校验 + AC6 |
| 恒等比对被行尾差异误伤 | 比对前 normalize CRLF（C6 明确） |
| 迁移期 sync 全红造成噪音 | [MIGRATE] 提示语 + 一次切换窗口短 |
| 宪法模板大改造成旧 clone 断裂 | README"先 pull+迁移指引"（C12）；07/17 手册自成体系可人工兜底 |
| 机器配置目录/文件误删 | 独立目录 + sync"在册非空而缺失"报 [FAIL] + ~/.zcode 状态快照恢复（AC7a/c） |
| 机器配置弱审计被无痕修改 | 文件末尾修订记录表 + sync hash 比对提醒补记 [WARN]（AC7b）——个人单机信任模型下的知情取舍 |
| 配置被当纯文本随手改（三区名牵动 vault 数据） | 配置模板说明列标注联动义务（§3.4） |
